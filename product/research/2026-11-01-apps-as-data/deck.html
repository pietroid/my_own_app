An app is three stored files

A screen in A2UI, its data as JSON, its actions as small JS. The agent builds the app once. AG-UI streams every change to the app as a JSON Patch.

Revises my_own_app #2 · 2026-11-02

This revises the apps-as-data RFC from my_own_app pull request 2. It is shorter, and it adds AG-UI as the wire between the server and the app.

The agent builds an app once; then the app runs without it

01 · STORE

A stored bundle

ui, data and actions, versioned. Opening the app regenerates nothing.

02 · RUN

A tap runs code

An action runs on the server in isolated-vm. 0 tokens, about 0.3 ms.

03 · NEW · SYNC

One patch, end to end

An action returns a JSON Patch. The server applies it to data and sends it as an AG-UI STATE_DELTA.

The first build is tiers 1 and 2, about 40% of 42 common app types. All four tiers reach 79%, an estimate.

The answer

The answer to the issue is yes, with corrections. The new part is the third card. The action's output, the storage update and the wire message are all one JSON Patch.

A bundle is a screen, its data and its actions

ui · A2UI v0.9

  "component": "Text",

  "component": "Button",
  "action": { "event": {
    "name": "add_expense"

data · JSON

{ "trip": {
  "title": "Lisboa",
  "budget": 8000,
  "expenses": [],
  "spentTotal": 0
} }

actions/add_expense.js

export const input =
  ['/trip/spentTotal'];
export function run(
  { spentTotal }, e) {
  return [
   { op: 'add', path:
    '/trip/expenses/-',
    value: e },
   { op: 'replace', path:
    '/trip/spentTotal',
    value: spentTotal
      + e.amount }];
}

The screen binds by path and names actions. It holds no values and no code.

Example: organize my trip to Lisbon. One build turn writes these three files. The action declares the paths it reads and returns a patch, never a whole new state.

Each tap runs a small stored function. Passing the whole state grows with every row, so each action declares the paths it reads, as Shopify Functions do. The network round trip costs more than the sandbox.

{ "type": "STATE_DELTA",
  "delta": [{ "op": "add",
    "path": "/trip/expenses/-",
    "value": { "amount": 40 } }] }

“STATE_DELTA delivers incremental updates to the state using JSON Patch format (RFC 6902).”

For us, the action’s output is already in the wire format, so we need no diffing and no second encoder.

AG-UI docs, State Management: docs.ag-ui.com/concepts/state

AG-UI is the event protocol between an agent and a front end. Its state model is a snapshot followed by JSON Patch deltas, which is exactly what our actions produce. Carrying A2UI in a CUSTOM event is our choice. Some integrations carry it inside a tool call instead.

A2UI draws the screen; AG-UI delivers it

A2UI v0.9: the payloadAG-UI: the transport
Describescomponents bound to data pathsevents between the agent and the app
Data updatesupdateDataModel: a value at a pathSTATE_DELTA: any JSON Patch (add, remove, move)
Actionsnamed events, registered in advancenone; we map each action to a run
Streamingnonetext, tool calls and steps, as they happen
We use it forthe screenthe wire and the data

Keep A2UI as the screen format. Send data as AG-UI state instead of A2UI’s updateDataModel.

Adding a row is then one add operation, not a rewrite of the whole array. The person also watches the build turn stream.

a2ui.org/specification/v0.9-a2ui · docs.ag-ui.com

The two protocols work at different layers, so the choice is not one or the other. A2UI stays the screen format, behind one encoder because v1.0 renames bindings. AG-UI replaces our hand-made reply format.

The agent writes the actions, so they run in isolated-vm, never eval

RunnerIsolation1 MB stateVerdict
eval · node:vmnone: “not a security mechanism”14 msRejected
isolated-vmits own V8 isolate, memory cap, timeout12 msChosen, run in a worker
QuickJS (WASM)an interpreter, nothing exposed62 msFallback
child processan OS process+ spawnToo heavy per tap

The person’s words reach the agent, so action code is untrusted. isolated-vm has a prebuilt arm64 binary for the Pi, but the project is in maintenance mode. If it stops being maintained, actions move to QuickJS without changing the contract (declared paths in, a patch out).

nodejs.org/api/vm.html · github.com/laverdet/isolated-vm · my_own_app #2 bench

Node’s own docs say vm is not a security mechanism. isolated-vm’s README advises running it in a separate process, and its memory limit is approximate, so we run it in a worker.

The tiers are cumulative. Tier 2 is the first build because the issue’s own example, the trip planner, needs a map. The largest cost is the catalog: app_ui has 3 widgets today and needs about 25.
